## 一、结论先说

现在的界面**不难看，但不像商业产品**，问题不在配色，在三点：

1. **样式是两套设计系统叠出来的。** `src/styles/main.css` 共 991 行，第 7–443 行是第一套（原单文件 SPA 遗留，靛紫渐变），第 455–990 行是第二套（注释写着「豆包风格 · Arco 色板」），同一批 CSS 变量被定义了**两遍**，后段覆盖前段，前段一半规则已是死代码。任何人改颜色都得先猜哪一遍生效。
2. **品牌是借来的。** Logo 颜色、气泡形状、空状态文案结构，都是豆包的形状。商业产品可以学交互，但不能让客户一眼认出是别人家的壳。
3. **功能只到「能用」，没到「敢卖」。** 没有重新生成、没有反馈、没有导出、没有设置面板、没有错误编号展示；提示用原生 `alert/confirm`；移动端把会话列表压成一条横向滚动条。

**建议路径**：不做框架迁移、不动后端接口，用 4 个迭代把视觉换皮 + 功能补齐，每轮可独立验收。

## 三、视觉重构方案

### 3.1 品牌定位（一句话）

> **不是聊天框，是「查数—审数—出结论」的工作台。**
> 所以视觉要「稳、准、可追溯」，不要「活泼、聊天感、玩具感」。

三条落地原则：
1. **去拟人化气泡**：助手答案不用圆角气泡，用「带左侧标识线的文档卡」——暗示这是可引用的结论，不是闲聊。
2. **克制的品牌色**：主色只出现在「可点击」和「有状态」的地方，其余全是中性灰阶。商业软件的贵气来自留白，不来自渐变。
3. **数据要有尊卑**：表格、SQL、来源卡片是「证据」，视觉层级高于正文。

### 3.2 色板（替换现有两套 token，只留一套）

**浅色**

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#F5F6FA` | 画布 |
| `--surface` | `#FFFFFF` | 侧栏、卡片、输入框 |
| `--surface-2` | `#F8F9FC` | 次级面板（计划/来源） |
| `--surface-3` | `#EFF1F7` | 行内 code、标签底 |
| `--ink` | `#0F172A` | 正文 |
| `--ink-soft` | `#334155` | 次级正文 |
| `--muted` | `#5B6478` | 说明文字 |
| `--muted-2` | `#8A92A6` | 占位、时间戳 |
| `--line` | `#E7E9F2` | 分割线、卡片描边 |
| `--brand` | `#2F4BD8` | 主色（靛蓝，比现用 `#165dff` 更深、更「企业」） |
| `--brand-soft` | `#EEF1FE` | 选中态底色 |
| `--gold` | `#B08430` | 仅用于 AI 身份标识（logo 内衬、来源徽章点缀） |
| `--ok` / `--warn` / `--err` | `#0F9D63` / `#B8791A` / `#D92B36` | 状态 |

**深色**

| Token | 值 |
|---|---|

| `--surface` | `#11151F` |
| `--surface-2` | `#161B27` |
| `--surface-3` | `#1C2230` |

## 四、功能补齐清单

> 每项给出：现状 → 方案 → 涉及文件 → 验收标准。**全部为前端改动，不需要后端配合**（除 F7 注明可选项）。

### P0（本轮必做，不做不能对外演示）

**F1 消息操作：复制 / 重新生成**
- 现状：只有复制，且有 B1 缺陷。
- 方案：
  - `copyAnswer` 改为组件内 `ref` 控制按钮状态（`copied` 布尔），不再全局查询；保留图标，只切换文字。
  - 新增「重新生成」：取当前消息前一条 user 内容，`chat.regenerate(index)` → 删除当前 assistant 消息 → 重新走 `sendQuestion`（不新增 user 气泡）。
- 文件：`MessageItem.vue`、`stores/chat.js`
- 验收：连续 3 条回答，点第 2 条的复制，只有第 2 条变「已复制」且图标还在；点重新生成后消息列表长度不变、回答被替换。

**F2 错误可追溯**
- 现状：`useChat.js:110` 只取 `final.message`，`final.error_id` 被丢弃。
- 方案：
  - `chat store` 的 assistant 骨架增加 `error: null | { message, errorId }`。
  - `useChat.js` 在 `type === 'error'` 与 catch 分支写入 `message.error`。
  - `MessageItem` 渲染 `.error-block`：人话一句 + 「错误编号 xxx」+「重试」。
- 验收：断开后端发一条消息，界面出现错误块并显示 8 位编号，点重试能重新发起。

**F3 统一 Toast / 确认框**
- 现状：`Sidebar.vue:43,50,63,65,71,72,85` 共 6 处 `alert` / `confirm`。
- 方案：新增 `composables/useToast.js`（队列、自动 2.6s 消失、可手动关）+ `components/ToastHost.vue`；`useConfirm()` 返回 Promise 的模态框，支持 `danger` 样式。
- 验收：删除会话弹自绘确认框，点「确定」后右上角出成功 Toast，浏览器无原生弹窗。

**F4 移动端会话抽屉**
- 现状：`main.css:972` 把 `.conv-list` 变成横向滚动。
- 方案：≤860px 时侧栏 `position: fixed` + `translateX(-102%)`，顶栏左侧加汉堡；加 `.side-mask` 遮罩；选中会话后自动关闭。
- 验收：375px 宽度下，点汉堡弹出侧栏、点遮罩关闭、切会话后自动收起。

### P1（第二迭代）

**F5 会话按日期分组 + 相对时间**

## 七、风险与约束

| 约束 | 说明 |
|---|---|
| **不改后端** | 本文所有功能前端可独立完成；仅 F7 反馈上报需要未来加 `POST /api/feedback` |

| **不引 CSS 预处理器** | 现有纯 CSS + `color-mix()` 已足够，加 Sass 只增加构建链 |
| **性能** | 新增依赖上限 0 个；字号缩放用 CSS 变量实现，不重渲染 |
